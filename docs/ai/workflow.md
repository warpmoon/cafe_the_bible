# Workflow & Reporting Rules

이 문서는 작업 계획, 승인, 수정, 완료 보고까지의 절차를 정의합니다.
파일을 수정하는 모든 작업 전후로 이 절차를 따릅니다.

## Interaction & Workflow Protocol

- **Plan-First Workflow:** 모든 파일 수정이나 시스템 변경 작업 전에는 반드시 아래 항목을 포함한 작업 계획을 한국어로 보고합니다.
  - **[원인 분석]**
  - **[작업 계획]**
  - **[예상 결과]**
  - **[영향도 분석]**
- **Explicit Approval:** 사용자의 명시적인 승인 전까지 실제 수정 도구 호출을 대기합니다.
- **Communication Style:** 모든 기술적 분석, 작업 계획, 완료 보고는 한국어로 간결하고 명확하게 작성합니다.

## Documentation Sync Rules

규칙은 정확히 한 파일에만 존재합니다.

- 백엔드 규칙: `.agents/skills/backend/SKILL.md`
- 프론트엔드 규칙: `.agents/skills/frontend/SKILL.md`
- 문서 규칙: `.agents/skills/docs/SKILL.md`
- 작업 절차와 승인 규칙: `docs/ai/workflow.md`
- 전역 규칙과 읽기 순서: 루트 `AGENTS.md`

컨벤션 변경 시, 그 규칙이 실제로 위치한 단일 파일만 수정합니다. 같은 내용을 여러 파일에 복제하지 않습니다.

## Change Classification

| 상황 | 규칙 문서 수정 |
| --- | --- |
| 기능 구현 또는 버그 수정 | 불필요 |
| 새로운 패턴 또는 규칙 도입 | 해당 단일 규칙 파일 |
| 기존 규칙 변경 또는 삭제 | 해당 단일 규칙 파일 |
| 디렉토리 구조 변경 | 해당 단일 규칙 파일 |
| 기술 스택 추가 또는 제거 | 해당 단일 규칙 파일 |

## Completion Report Format

작업 완료 후 아래 형식으로 보고합니다.

```markdown
#### 작업 완료 보고

[백엔드/프론트엔드/문서/공통] 제목

**[문제 및 요청 요약]**
작업 내용 요약

**변경 유형**
- [ ] 기능 구현 또는 버그 수정
- [ ] 컨벤션 신규, 변경, 삭제

**수정 파일**
- `파일 경로`: 변경 내용

**검수 결과**
- 실행한 명령 또는 생략 사유
```
